# NewsLens Official & Regulatory Sources — Plan (for approval)

**Date:** 2026-07-04 · **Scope:** government/regulator/central-bank notices + exchange & company filings (India, US, UK, EU, Japan, China), **English only** · **Verification standard:** every feed below was fetched live with `curl --max-time 20 -A "NewsLens/0.1 (RSS Reader)"`; VERIFIED = HTTP 200 + XML/RSS/Atom marker in first 2KB + channel-title identity (CDATA-aware). 34 verified, **47 rejected with recorded reasons**. Research: 5 regional verifier agents + 1 architecture agent grounded in the live codebase.

---

## 1. Executive summary

Two new source tiers on top of the existing gated machinery (research/expert, PR #77/#84/#91):

- **`official`** — regulator / central-bank / ministry / exchange notices (RBI circulars, SEC & Fed press, GOV.UK, ECB, BoJ…). Audience-gated exactly like research: finance/policy/law professions get them by default; everyone else opts in via follow-source or the discover deck. 28 verified feeds ready to seed.
- **`filing`** — per-company disclosures (SEC EDGAR 10-K/10-Q/8-K; later NSE/BSE corporate announcements). **Never bulk-seeded** — generated per watchlisted ticker (the `arxiv_gen` pattern), invisible to everyone except watchlist holders. The EDGAR per-CIK Atom pattern is verified.

Reuses everything Phase 1–3 built: the six credibility columns, `allowed_source_ids` gating, floors, follow-override, `per_fetch_cap`, admin-lock, badges, the `?source_type=` filter, and the generated-source patterns (`arxiv_gen`/`pubmed`).

## 2. ⚠️ Urgent — two ALREADY-SEEDED feeds are broken (fix in Phase 1 regardless)

1. **PIB India is serving HINDI.** The seeded feed (`pib.gov.in/RssMain.aspx?ModId=6&Lang=1&Regid=3`) ignores the `Lang` parameter server-side — Lang=1/2/3 return byte-identical Hindi output. This violates English-only **today** and pollutes the embedding space. Fix: language-gate at ingestion (ASCII-ratio heuristic on the title — cheap, no LLM) and/or drop the feed until PIB fixes it. No usable English PIB feed exists (all ModIds probed: photos, Hindi, 404s).
2. **SEBI item links are malformed** — double-prefixed URLs (`https://www.sebi.gov.in/https://www.sebi.gov.in/...pdf`). Fix: normalize double-scheme URLs in `fetch_single_feed` link handling (also protects dedup keys).

## 4. Architecture (grounded in the live code)

### 4.1 Two new enum values — `official` + `filing`
`SourceType` gains both in **one migration** (the derisked `b2c3d4e5f6a7` pattern: `autocommit_block()` + `ADD VALUE IF NOT EXISTS`; **no new columns** — all six Phase-1 columns are reused; enum values are irreversible, an unused label is harmless). Why not reuse `wire`: (1) `wire` is ungated → RBI circulars would hit every user; (2) the `?source_type=news` chip is defined as `notin_(gated)` — officials must be separable from Reuters; (3) badges/filters branch on the type string (`OFFICIAL`/`FILING` badges are one-line additions). Why two values, not one: **their admission logic differs** — official is audience-gated by profession; filing is watchlist-gated per company and must never enter the discover deck's random gated sample.

### 4.2 Gating posture
One shared constant in `audience.py`: `GATED_SOURCE_TYPES = (research, expert, official, filing)`, consumed by `allowed_source_ids` and the four duplicated `[research, expert]` literals in `routes.py` (feed filter, briefing tier, deck, field-match). **But** the discover deck keeps its own `DISCOVER_SAMPLE_TYPES = (research, expert, official)` — **excluding filing** — or a stranger's 10-Q becomes a discover card. Officials are seeded with real audience tags (RBI/Fed → `["finance","economics","policy"]`; DOJ → `["policy","law"]`) and credibility 88–98 (primary sources; clear both floors) → they flow to matching professions exactly like NEJM flows to doctors. Filings are seeded `audience=[]` → invisible except via the follow/watchlist branch. Pre-seed responses stay byte-identical (no rows carry the new types until seeded).

### 4.3 Volume control (Phase-1 discipline, not later)
(1) `per_fetch_cap` on every official seed (verifier-recommended values in the seed JSON; **`per_fetch_cap=0` means UNCAPPED** in `_capped_entries` — never use 0 as "pause"). (2) **EDGAR is never bulk-ingested** — sources exist only per watchlisted ticker, cap 10, plus an ingest-side form whitelist (`edgar_form_types = "10-K,10-Q,8-K,20-F,6-K"`; EDGAR Atom titles start with the form type, so a small `fetch_single_feed` branch drops non-whitelisted forms — kills the Form-4/13F noise that is ~80% of a large-cap's feed). (3) `edgar_max_companies = 50` enforced in the generator (fetch_all_rss hits every source every 10 min). Rank-side comes free: officials/filings get the same bounded ×[0.9,1.1] credibility multiplier and become singleton clusters (boilerplate won't merge with news at cosine 0.15), so the briefing window is protected exactly as it was for arXiv.

### 4.4 Watchlist filings (Phase 2) — `edgar_gen.py`
A fusion of `arxiv_gen` (spec-dict → `_upsert_sources`, idempotent, admin-lock honored) and `pubmed` (reads user state, own job): collect distinct `{type:"ticker"}` values from `User.watchlist` JSONB → resolve ticker→CIK via `sec.gov/files/company_tickers.json` (fetched once per run; unresolvable tickers logged + skipped — watchlist values are free text: "NVDA", "nvda", "NSE:RELIANCE") → emit one `filing` source per company with the per-CIK Atom URL → daily job. Requires the per-domain SEC UA (config `sec_user_agent` with a real contact email). Filing bodies are thin (Atom index stubs) — cards render title-only; a Phase-3 document-fetch lens deepens them. Filings attach naturally to company entities (cast strip) via the existing research-singleton extraction relax.

### 4.5 English-only enforcement
A cheap ingestion guard (ASCII-ratio heuristic on the title, config-gated) applied to sources flagged `credibility_meta.english_guard=true` — needed **today** for PIB (Hindi) and defensively for any gov feed that language-flips. No LLM cost.

## 5. Phased rollout (~4–5 dev-days)

| Phase | Scope | Effort | Exit criteria |
|---|---|---|---|
| **1 — Official tier + seed + hygiene** | Migration (2 enum values, no columns); `GATED_SOURCE_TYPES` refactor (+ deck exclusion of filing); seed the 28 verified officials; `OFFICIAL` badge + chip; PIB language-gate + SEBI URL-normalize fixes; NITI fetch-timeout headroom; `create_source` validation for the new types; exclude `official` from the monthly LLM credibility review (scoring the Fed is meaningless) | 1.5–2d | finance-profession user sees RBI circulars + Fed pressers in feed/briefing; poet's feed byte-identical; PIB Hindi stops entering the corpus; suite green |
| **2 — EDGAR watchlist filings** | `sec_user_agent` per-domain UA; `edgar_gen.py` (ticker→CIK→per-CIK Atom source, `edgar_max_companies`); ingest form-whitelist branch; daily job; `FILING` badge | 1.5d | watchlisting NVDA yields NVDA's 8-K/10-Q in that user's feed within a day; non-holders see nothing |
| **3 — India exchange filings + depth** | NSE/BSE corporate-announcement adapter (nsearchives feeds; watchlist-matched at ingest); filing→entity attach; optional filing-summary lens (quarterly key numbers) | 1.5–2d | watchlisting RELIANCE yields its BSE/NSE announcements; filings appear on the company's cast strip |

**Top risks:** the `GATED_SOURCE_TYPES` refactor leaking filings into the discover deck (mandated split constant); the News chip silently narrowing when officials leave the `notin_` bucket (intended — QA note, not regression); nsearchives/EDGAR UA fragility (feeds die silently — watch `/admin/breadth` staleness); feed rot (30–50% quarterly — the 28 seeds re-verify at implementation time).

## 6. Open decisions (owner calls before implementation)

1. **Filing visibility:** strict watchlist-only (`audience=[]`, recommended) vs `audience=["finance"]` (every finance user sees every watchlisted company's filings).
2. **Briefing bonus:** does `official` earn the field-match +0.15 (recommended: yes — a Fed decision belongs in a finance user's top-8; slight top-8 crowding).
3. **GOV.UK:** seed the 40–80/day all-announcements firehose (cap 15) or department feeds only (HM Treasury seeded; add FCDO/DBT later)?
4. **EDGAR form whitelist:** minimal 10-K/10-Q/8-K vs + 20-F/6-K (ADRs — recommended if users watchlist foreign issuers) vs + S-1 (IPO watchers).
5. **`edgar_max_companies`** ceiling (50 proposed) + job cadence (daily 05:00 proposed).
6. **SEC contact email** for the declared UA (must be real).
7. **Badge copy:** `OFFICIAL` vs `REGULATOR`/`GOVT`; `FILING` vs `DISCLOSURE` (must pass `lint:copy`).
8. **Filing-source retirement** when a ticker leaves all watchlists: leave running (harmless at ≤50) vs prune (recommended: leave; revisit at scale — and never "pause" via cap=0, which means uncapped).
