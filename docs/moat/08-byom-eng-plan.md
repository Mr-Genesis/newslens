### `_generate_anthropic` shape (official `anthropic` SDK, async, assistant-prefill JSON)
Mirror `_generate_gemini` with Anthropic's API differences:
- Lazy `import anthropic`; `client = anthropic.AsyncAnthropic(api_key=key)` (fresh per call, like `_get_client_async`).
- Key: `key = settings.anthropic_api_key if force_platform_key else await _resolve_anthropic_key()`; `if not key: raise LLMUnavailable("no Anthropic key configured")`.
- `messages = [{"role": "user", "content": user_prompt}]`. When `schema is not None`, **prefill the assistant turn** to force pure-JSON output: append `{"role": "assistant", "content": "{"}` and parse `"{" + resp_text` (deterministic JSON, the idiomatic Anthropic technique with no `response_format`). When `schema is None`, no prefill.
- `system` is TOP-LEVEL: `await client.messages.create(model=resolved_model, max_tokens=max_tokens or 800, messages=messages, **({"system": system} if system else {}))`. `max_tokens` is REQUIRED. **No `temperature`** (omit it).
- Extract text from content blocks: `text = "".join(b.text for b in resp.content if getattr(b, "type", None) == "text")`. For the schema path, parse `extract_json("{" + text)` (prefill makes this a clean object). For the non-schema path, return `text.strip()`.
- (Refusal guard DEFERRED per product cut â€” `extract_json` failure already degrades gracefully; add a `stop_reason=="refusal"` branch only if a real refusal is observed.)
- `_resolve_anthropic_key()` copies `_resolve_gemini_key()` with its OWN cache slot (`_anth_key_cache`/`_anth_key_ts`, 300s), querying `anthropic_api_key_encrypted` + `anthropic_key_verified is True`, env fallback `settings.anthropic_api_key`.

## Risks
- Anthropic model ids (`claude-haiku-4-5`) are placeholders â€” they MUST be confirmed against the live Anthropic model list at implementation time, since config already shows drift (`gpt-4o-mini`, `gemini-2.0-flash`). A wrong id makes test-anthropic-key (max_tokens=1 call) fail with NotFoundError even on a valid key. Mitigation: confirm the id before S2/S4; env override always wins; this is precisely why we hardcode the list instead of a server catalog.
- S6 is the highest-impact correctness fix: if the active/background provider is switched to Anthropic while `graph_extraction_model='gpt-4o-mini'` is still passed explicitly, every background cluster 400s on `AsyncAnthropic.messages.create`. The `model=None` fix relies on each `_generate_*` defaulting to its own provider â€” verify S2's default-model path is exercised by the S6 test (capture the kwarg), not assumed.
- `extract_json` widest-span heuristic remains fragile for the non-prefill path; the plan removes that risk for Anthropic by using assistant-prefill (`'{'`) so parsing is deterministic. If a future caller bypasses prefill (e.g. a non-schema call that still expects JSON), the prose-sandwich failure returns ValueError â†’ unavailable/skip, not a crash. Acceptable but document it.
- Sequencing trap: `UserSettingsUpdate` currently drops unknown fields silently. If S7/S8 (frontend) merge before S4 (schema), `active_provider`/`anthropic_model` writes return 200 and vanish, masking the bug. Hard rule: S4 lands + its negative test passes BEFORE S7/S8. Adding `extra='forbid'` to `UserSettingsUpdate` is recommended so typo'd fields fail loudly.
- `_active_provider()` adds a DB read on the generation hot path; the 300s TTL cache mitigates it but means a provider switch in Settings takes up to 5 min to fully propagate to all callers. Documented + tested (S1 cache test). If instant switch is ever required, add explicit cache invalidation on the settings PUT â€” out of scope for slice 1.
- test-anthropic-key error redaction must NOT copy the `str(e)[:200]` precedent from `test_gemini_key` (routes.py:1154) â€” Anthropic exception `__str__` can echo request metadata/the key. The S4 catch-all returns a fixed string; the redaction test guards it. The Gemini leak is pre-existing and out of scope (do not propagate it).
- Dependency resolution on Windows-ARM/Docker: `anthropic>=0.40` pulls its own httpx/pydantic pins; must coexist with `openai==1.59.5`, `google-generativeai==0.8.3`, `pydantic==2.10.4`. S0 verifies install + Docker build before any code depends on it. Also fixes the pre-existing duplicate `httpx==0.28.1`.
- Embeddings must stay on OpenAI (hard constraint): `embeddings.py` is untouched and `_active_provider()`/the anthropic branch never route embeddings. Verify no accidental import of `generate()` into the embedding backfill path during review.
